This directory contains build scripts for energy solvers and their dependencies

System requirements:
- Processor must have AVX support
- conda (https://github.com/conda-forge/miniforge#unix-like-platforms-macos-linux--wsl)

Run the build/install scripts in this order:

`install_nvhpc.sh` - this script installs nvidia's hpc sdk which is needed for tools like mpirun and for its nvc++ compiler (and not the "plain" nvcc)

`build_dice.sh` - this script builds the `Dice` binary used by the `"dice"` solver, **without** needing admin rights (or docker). Point the solver at it with `DICE_BINARY` (or `DICE_BIN_DIR`, or `Dice` on `PATH`)

`build_sbd.sh` - this script prepares the native prerequisites (MPI/BLAS, and the NVIDIA HPC SDK for GPU) for the in-process `sbd-eigensolver` package that backs the `"sbd"` solver (TPB + GDB modes). By default it **auto-detects** whether a GPU build is possible by checking for the `nvc++` compiler (the GPU toolchain). When `nvc++` is found it prepares a GPU-capable build (`SBD_BUILD_BACKEND=all`, CPU + Thrust GPU + OMP-offload GPU in one venv); otherwise it falls back to a CPU build. A GPU build targets **one** architecture: by default the compute capability of the GPU `nvidia-smi` reports (building on a GPU node). On a node without a working `nvidia-smi` (e.g. a login node) `SBD_GPU_ARCH` gives the target GPU (`cc80` for A100, `cc90` for H100), one build per GPU model; without it the script stops. Several architectures in one build are not supported: with NVHPC 26.9 such a binary runs correctly only on the first one listed (NVIDIA/cccl#11572). Force a mode with `SBD_BUILD_BACKEND=cpu|gpu|all` or skip detection with `SBD_SKIP_GPU_DETECT=1`. If you ran `install_nvhpc.sh` first, this script finds that locally-installed HPC SDK automatically (nvc++ compiler and its bundled OpenMPI) — no `module load` or manual `NVHPC_HOME` needed — and writes the SDK's `bin`/`lib` (and CUDA runtime) onto `PATH`/`LD_LIBRARY_PATH` in the env file so both the build and later `uv run` resolve the compiler, MPI wrappers, and runtime libs. It does NOT build the package itself; after running it, `source build/energy_solvers/sbd_env.sh` then install with `uv sync --extra sbd`, which compiles `sbd-eigensolver` against the prepared toolchain. Verify the compiled backends with `uv run python -c "import sbd; print(sbd.available_backends())"` (`['cpu']` vs `['cpu', 'gpu', 'gpu-omp']`).

`build_evsl.sh` - this script builds [EVSL](https://github.com/eigs/EVSL) (EigenValues Slicing Library) as a **shared** library for the matrix-free EVSL spectrum-slicing solver (backed by the ctypes wrapper in `sci_solvers.energy_solvers.evsl`, registered as `solver="evsl"`). EVSL is a polynomial/rational-filter Lanczos solver for *interval* eigenvalues — it finds every eigenvalue in a window `[lo, hi]` rather than the lowest `nroots`. The build is standalone (autotools, no admin rights, no MPI): on macOS it links Apple Accelerate; on Linux it uses conda-forge openblas. To link a custom BLAS/LAPACK on either platform, set `BLAS_LIB_DIR` (plus optional `BLAS_LIB_NAME`/`LAPACK_LIB_DIR`/`LAPACK_LIB_NAME`, defaulting to a single `openblas` exporting both), or use the `OPENBLAS_ROOT` shorthand. Artifacts land in the gitignored `build/energy_solvers/evsl_workdir/`. After building, point the solver at the shared library it prints via `export SCI_SOLVERS_EVSL_LIB=<path to libevsl.{dylib,so}>` (the wrapper also searches the system loader path and this build tree). There is no PyPI package for EVSL — this script is the only way to install it.
